## What GenV1 is

GenV1 (working directory `genV2_Interface_projectManager/`) is a local lab for
building and testing AI agents: a **FastAPI** backend + vanilla-JS frontend +
**Ollama** local LLMs. An agent is a reusable Python runtime (think / act /
observe) whose behavior is a markdown file, whose configuration is a JSON file,
and whose capabilities are registered tools.

| Attribute | Value |
|---|---|
| Identity | GenV1 |
| Project root | `genV2_Interface_projectManager/` |
| Backend | FastAPI (`server/server.py`) |
| Frontend | Dashboard (`dashboard/`), vanilla JS |
| LLM runtime | Ollama (local models) |
| Data authority | `server/paths.py` (env var → per-OS key → plain key → default) |

## Documentation authority rules

When two parts of the documentation disagree, trust in this order:

```text
1. Running source code
2. Active configuration files
3. Actual filesystem structure
4. Tests / verified runtime behavior
5. Generated source snapshots
6. Architecture documentation
7. README / user documentation
8. Historical changelog
```

The **source code wins**. Historical behavior is preserved in the changelog but
is not presented as current architecture.

## Recommended AI reading order

An AI agent (or new human) should read GenV1 in this chain so each document
builds on the previous one and references resolve to real files:

```text
docs/INDEX.md
    ↓
docs/BLUEPRINT.md
    ↓
docs/architecture/SYSTEM.md
    ↓
(relevant architecture document)        e.g. docs/architecture/AGENTS.md
    ↓
(relevant reference document)           e.g. docs/reference/AGENT_REFERENCE.md
    ↓
(relevant workflow)                     e.g. docs/reference/WORKFLOWS.md
    ↓
source code                             e.g. engine/core/agent.py
    ↓
context                                 docs/living/CHANGELOG.md · CURRENT_STATE.md
```

### Subsystem reading maps

To understand a subsystem end to end, follow its path chain:

- **Agents** → `architecture/AGENTS.md` → `reference/AGENT_REFERENCE.md` →
  `reference/WORKFLOWS.md` (chat/pipeline) → `engine/agent_library/*/agent.md`
- **Tools** → `architecture/TOOLS.md` → `reference/TOOL_REFERENCE.md` →
  `development/ADDING_TOOLS.md` → `tools/tools.py`
- **Custom modules** → `architecture/INTERFACE.md` →
  `development/CUSTOM_MODULES.md` → `interface/custom_module_manager.py`
- **Data & config** → `architecture/CONFIGURATION.md` →
  `architecture/DATA.md` → `server/paths.py` → `dashboard/config/app_settings.json`
- **History & state** → `living/CURRENT_STATE.md` → `living/CHANGELOG.md` →
  `living/KNOWN_ISSUES.md` → `living/TODO.md` → `living/DECISIONS.md`

## Regenerating generated documentation

```powershell
venv\Scripts\python scripts\update_documentation.py
```

`docs/generated/APP_STRUCTURE.md` and `docs/generated/APP_CODE_SNAPSHOT.md` are
created by `scripts/update_docs.py`; `docs/BLUEPRINT.md` is assembled by
`scripts/update_blueprint.py`. None of the `docs/living/` documents are ever
overwritten by automation. See `docs/development/DOCUMENTATION_RULES.md`.
